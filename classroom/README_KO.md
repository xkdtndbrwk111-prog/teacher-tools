# 교실 매니저 Stage 04.6

자리배치와 성적 관리를 합친 시험판입니다. **가상 학생 자료로만 시험하세요.** 공개 사이트와 Google 계정에는 아무것도 올리지 않습니다.

## 개발 중 로컬 실행

공개 주소 없이 시험할 때만 씁니다. 주소가 달라 자료는 공개 주소와 따로 저장됩니다.

- **Windows:** `classroom/시작하기.cmd` (설치 불필요)
- **Mac:** `classroom/시작하기.command` (Node.js 20 이상)

주소는 `http://127.0.0.1:4188/seating/`입니다.

## 대시보드와 함께 쓰기

교실 매니저는 웹에서 실행됩니다(`https://xkdtndbrwk111-prog.github.io/teacher-tools/seating/`). Teacher Tools 대시보드 V1.11이 깔린 PC에서 칠판으로 보낼 수 있습니다.

- `칠판으로 보내기`를 누르면 작은 창이 잠깐 열려 대시보드로 자리표를 넘기고 닫힙니다. 한 번 성공하면 다음부터 배치 확정 때 자동으로 보냅니다.
- 대시보드의 `자리배치`를 열면 연습과 실전을 고릅니다.
- `실전 자리배치`는 경고창 뒤 확정한 자리를 보여 줍니다. 여러 번 눌러도 자리는 같습니다. 새로 확정해 보내기 전까지 바뀌지 않습니다.
- `연습 자리배치`는 마지막에 보낸 명단으로 매번 새로 섞습니다. 남녀 좌석 규칙만 지키고 저장하지 않습니다.
- 전달되는 것은 이름, 캐릭터, 성별, 좌석, 모둠, 짝 반응 대사입니다. 성적, 체육 능력치, 지정석과 떨어뜨릴 학생 정보는 전달되지 않습니다.
- 브라우저가 작은 창을 막으면 이 사이트의 팝업을 허용하세요.

## EASY와 NORMAL

상단의 저장 표시를 눌러 고릅니다.

- **EASY:** 이 브라우저에만 저장합니다. PC를 옮길 때는 전체 백업 파일을 씁니다.
- **NORMAL:** 브라우저에 바로 저장하고, 교사 본인의 구글 시트에도 저장합니다.
  - **구글 저장 시점:** 마지막 변경 5분 뒤(계속 입력해도 20분 안에는 저장), 배치 확정과 평가 생성 직후, `지금 저장`을 누를 때
  - **자료 차이:** 다른 PC에서 저장했거나 양쪽이 바뀌면 묻습니다. 고르지 않은 쪽은 백업 창의 되돌리기에 남습니다. 학생 화면이 열려 있는 동안에는 창을 띄우지 않습니다.
  - **로그인:** 구글 정책상 약 1시간이면 끝나고, 다시 연결은 버튼을 눌러야 합니다. 그동안에도 브라우저에는 계속 저장됩니다.
  - **파일:** 학년도마다 `교실 매니저 2026학년도` 파일 하나를 만듭니다. `TT_DATA` 탭이 원본이고, 성적 탭은 보기용입니다. **시트에서 고친 값은 프로그램에 반영되지 않습니다.**
  - **시트에 없는 것:** 잠금 번호, 복원 되돌리기, 삭제한 반 복구 목록
  - **개인정보:** 학생 이름, 성적, 체육 능력치가 교사의 드라이브에 암호 없이 저장됩니다. 학교 기준을 먼저 확인하세요.

### Google 연결값

연결값은 `classroom/grades/google-config.mjs`에 들어 있습니다. 지금은 Google에서 **테스트 상태**라 테스트 사용자로 등록한 계정만 로그인할 수 있습니다. 새로 만들 때의 순서는 아래와 같습니다.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만듭니다.
2. **Google Sheets API**와 **Google Drive API**를 사용 설정합니다.
3. OAuth 동의 화면을 만들고, 시험 중에는 사용할 계정을 시험 사용자로 추가합니다.
4. **사용자 인증 정보 > OAuth 클라이언트 ID > 웹 애플리케이션**을 만듭니다.
5. 승인된 JavaScript 원본에 쓰는 주소를 모두 넣습니다: `https://xkdtndbrwk111-prog.github.io`, `http://127.0.0.1:4188`, `http://localhost:4188`
6. 만들어진 ID를 `classroom/grades/google-config.mjs`의 `GOOGLE_CLIENT_ID`에 넣습니다.

## 저장 방식

- 자리배치, 체육, 성적, 반 목록을 IndexedDB 저장소 하나(`tt-classroom-v1`)에 둡니다.
- 복원, 반 삭제, 반 복구, JSON 불러오기는 한 번의 저장으로 처리합니다. 도중에 꺼지면 전부 이전 상태로 남습니다.
- 입력은 저장이 확인될 때까지 짧은 임시 기록을 함께 남기고, 다음 실행 때 이어서 반영합니다.
- 교실 매니저는 한 브라우저에서 탭 하나로만 열립니다. 한자 매니저는 함께 열 수 있고, 현재 반 명단의 복사본만 읽습니다.
- 처음 실행할 때 04.1 자료와 기존 자리배치 자료를 옮깁니다. **옛 자료는 지우지 않고 그대로 남습니다.**

## 복구

- **삭제한 반:** 반 관리 창 아래 목록에서 성적까지 복구하거나 완전 삭제합니다. 이번 학년도 성적만 복구 대상이며, 지난 학년도 성적은 지워지지 않습니다. 삭제한 반은 30일 동안 남은 뒤 자동으로 지워지며, 그 전에 완전 삭제할 수도 있습니다.
- **복원 되돌리기:** EASY · 백업 창에서 직전 복원을 되돌립니다. 복원 전 파일도 함께 내려받습니다.
- **제외한 학생:** 성적 관리 > ② 학급 · 학생에서 다시 연결합니다.

## 잠금

- 상단 `잠금 만들기`에서 숫자 4~8자리 번호를 정합니다. 그때 보이는 복구 코드는 다시 볼 수 없으니 적어 두세요.
- 다시 열 때, 정해 둔 시간 동안 쉬었을 때, `잠금`을 눌렀을 때 잠깁니다. 학생 화면에서 교사 화면으로 돌아갈 때도 번호를 묻습니다.
- 학생 화면이 열려 있는 동안에는 자동으로 잠기지 않습니다.
- **잠금은 화면을 가리는 기능입니다.** 저장된 자료를 암호화하지 않습니다. 브라우저 개발자 도구를 쓸 줄 아는 사람은 자료를 볼 수 있습니다.
- 번호와 복구 코드를 모두 잃으면 잠금을 풀 수 없습니다. 이때는 브라우저의 사이트 데이터를 지우고 백업 파일로 복원합니다.

## 백업

- 전체 백업 파일은 기본으로 암호를 걸어 저장합니다 (AES-GCM). **암호를 잊으면 열 수 없습니다.**
- 복원 전에 내려받는 파일에도 암호를 겁니다.
- 자리배치 설정의 `JSON으로 내보내기`는 지금 반 하나만 담고 암호가 없습니다. 저장 전에 안내합니다.
- 예전 버전이 남긴 자료는 백업 창의 `이전 버전 자료 지우기`로 지웁니다.

## 학년도

- 성적 관리 메뉴의 `학년도`에서 지난 학년도를 고르면 **읽기 전용**으로 봅니다. 지금 명단이 지난 학년도에 섞이지 않습니다.
- 3월이 되면 새 학년도가 자동으로 열리고, 지금 명단이 새 학년도에 연결됩니다.

## 번호

- 번호는 명단 순서를 따르지 않습니다. 새 학생은 맨 뒤 번호를 받습니다.
- 성적 관리 > ② 학급 · 학생 > `번호 수정`에서 바꿉니다.

## 아직 남은 제한

- 자료는 이 브라우저에만 있습니다. 사이트 데이터를 지우거나 PC를 바꾸면 사라지므로 전체 백업 파일을 보관해야 합니다.
- 전체 백업 파일에는 삭제한 반 복구 목록이 들어가지 않습니다.
- 내부 저장 이름에는 `stage03` 같은 옛 이름이 남아 있습니다. 화면에는 보이지 않습니다.
- Windows 실행 파일(`server.ps1`, `시작하기.cmd`)은 Mac에서 실행해 볼 수 없어 **아직 한 번도 실행되지 않았습니다.**
