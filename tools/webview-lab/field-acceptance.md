# Phase 6 — 현장 인수 및 출시 승인 기준

**현재 상태: 수동 설치 후보. 정식 배포 금지.** Phase 5D 격리 환경의 성공은 실제 학교 PC의 성공을 의미하지 않는다. 모든 단계에서 운영 호자보드, 실제 학생 명단과 코인, 기존 브라우저 프로필을 보존한다.

| 단계 | 자동 검증 | 현장 승인 |
|---|---|---|
| 6A | 별도 설치/재실행/종료, 기존 설치 보존, 패키지 해시 변조 거부 | 실제 Windows 설치, Smart App Control과 정상 코드 서명 |
| 6B | 제공자 URL 정책 및 거부 경로 | 실제 아몬드 로그인/125쪽 복원/페이지 점프, 학급어린이회의 Canva·YouTube, 권한 있는 영상 다운로드/취소, NEIS/날씨, 온라인 미니게임·교실매니저의 별도 포트 규격 |
| 6C | 화면 목록/선택·창 모드/바탕화면 모드·격리 설정 | 85인치 터치, 키보드·공유 입력, 두 모니터 연결/해제, 실제 스피커·음량·음소거 및 복귀 |
| 6D | 기존 R8 로컬 시험의 서명/변조/롤백, 원본 백업/복원 회귀 | 설정 전용 백업을 먼저 복원, 이후 승인된 교실 데이터 이전·대조, 사진/미디어·쿠키의 별도 처리, 서명된 설치 신뢰 체인과 실제 네이티브 서버를 포함한 업데이트·실패 롤백 |
| 6E | CI의 원본 무결성 및 설치 검증 | 위 필수 항목 전부 PASS, 실제 설치판 서명, 배포 채널 승인, 복구 경로 확인 |

## 현장 결과 기록

각 항목마다 Windows 버전, 패키지 commit/manifest SHA256, 실행 모드, 검사 시각, PASS/FAIL/BLOCKED, 재현 절차를 남긴다. 학생 개인정보, Canva 로그인 쿠키, 영상 접근 토큰은 기록하지 않는다.

### 6B/C 명시적 시험 옵션
- 기본 실행은 외부 제공자 차단. `-LiveBook`: 원본 독립 책 재생기. `-LiveProviders`: Canva 조회·YouTube embed와 지정된 CDN 및 NEIS/날씨.
- `-LiveDownload`: 권한 있는 콘텐츠만. `-LiveAudio`: 실제 Windows 출력 장치 변경 허용(시험 종료 후 원래 장치/볼륨을 직접 확인하고 복귀).
- `-LiveSystem`: 지정된 파일·시스템 동작. `-LocalManager`에서 분리된 Chrome/Edge 프로필과 로컬 매니저 주소만 허용. 공개판 교실매니저 호출은 차단 상태 유지.
- `-Display`: 실제 장치 이름 선택. `field-device-report.json`으로 화면 크기·위치 확인. 개인화 데이터는 기록하지 않음.
- 후보판은 별도 패키지의 미니게임 4189·교실매니저 4188 출처로 고정하고 공개판 17439 연결을 하지 않는다. 자동 시험에서 실제 미니게임 ready/close 및 Chrome 매니저 부팅·capability를 확인한다. 실제 현장 코인 차감/환불·좌석/명단 전송·발표까지 검증 전에는 운영 연결을 승인하지 않는다.

### 6D 명시적 이전
- 원본 운영판에서 먼저 설정 전용 백업을 생성하고, 시험판에 사용자가 직접 선택한 파일만 가져온다. `-Transfer` 실행에서 시험판의 로컬 .ttbackup 저장 대화상자를 허용한다.
- 새 빌드는 manifest source별 독립 루트를 사용한다. 원래 운영판이나 이전 시험판을 덮어쓰지 않는다. 기존 테스트 데이터를 자동으로 옮기지 않는다.
- 운영용 신뢰 루트/서명 키/피드 갱신, 실제 native-server 포함 R8 allowlist 및 부팅 어댑터는 별도 승인 전까지 변경 금지.
- 시험용 자체 생성 서명과 실제 출시 서명은 구분한다. 자동업데이트 연결이 완료되었다고 표시하지 않는다.

### 6E 차단 조건
자동 CI 통과 시에도 후보 artifact만 생성한다. 현장 승인/설치 신뢰 체인/운영 데이터 및 업데이트 이전이 미검증이면 정식 배포하지 않는다. 이 문서는 승인 결과가 아닌 승인 기준이다.

### 설치형 통합 시험의 선행 조건
- 최초 학교 설정 창이 열린 상태에서는 학생 발표를 거부하는 기존 보호 정책을 유지한다. CI의 통합 시험만 실제 학교 API를 통해 가상 학교 설정을 준비하고, 설정 UI가 완료된 뒤 시험한다. 현장 설치에서는 사용자가 직접 학교를 선택한다.
