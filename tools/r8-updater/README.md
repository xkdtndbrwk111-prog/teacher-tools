# R8 signed runtime updater — review candidate

R6/R7 only update signed dashboard.html and release.json. R8 installs one fixed bootstrap (launch.ps1 + r8-kernel.ps1 + existing update-public.xml). Future manifests are exact-byte RSA-2048 PKCS#1 SHA256 signatures, with the same trusted public key. The signed inventory lists names, sizes and SHA-256; only changed files are downloaded from the fixed content-addressed blob path. Max 16 MiB/file, 64 MiB total. No redirects, arbitrary download URLs, path traversal, alias names, unsigned program files, credentials, profiles or ledger files. Fixed bootstrap, signing key, installer and uninstall entrypoint are not remotely replaceable. New executable filename or removal needs a reviewed manual migration; named graphic asset-* files may be added.

Before swaps: verify all downloads; explicit manual update may gracefully close only the dedicated board; automatic update never closes an open board. Verify all old copies and write pending journal with write-through before mutations. Per-file atomic replace; recovery before reading mutable runtime; successful new server, positioned board window and matching readiness token required before committing. Failure or interrupted power leaves journal for next safe cold launch. If a board is still open, never force-stop its browser; recovery is deferred to normal closure. No data migration is part of this protocol: incompatible user-data schema changes require separate migration/rollback design.

## Integrate only after R7 is assembled and validated

`python tools/r8-updater/apply-r8.py PATH/system --version 1.X.Y --release YYYY-MM-DD-V1.X.Y-STABLE-PILOT`. Use actual chosen release identity; dashboard label must also match the chosen identity. This stages candidate and recalculates checksum manifest. Manually install candidate once only after Windows launch/upgrade/rollback and all paired modules are verified. Keep R7 and R8 production feeds independent.

`python tools/r8-updater/prepare-feed.py prepare BASE/system TARGET/system NEW_OUTPUT` produces unsigned exact payload and sha-addressed blobs. Sign payload bytes offline with existing authorized RSA private key (never commit or upload the key), then `python tools/r8-updater/prepare-feed.py envelope NEW_OUTPUT signature.bin`. Independently verify signature against installed update-public.xml before publishing blobs first and latest.json last at stable/runtime-v1/. Do not change content-v4 or publish unsigned candidate. Feed is not created by this branch.

Tests use temporary fixture bytes, ephemeral RSA test key, and no live data. The fixture does not execute a real board or install production keys. Real Windows monitor/browser restart, interrupted update, installer lock, package/signing and release verification are required before promotion. Existing update UI auth, startup preference and hidden launch are preserved. No administrator permissions required by updater under normal per-user installation; physical Windows testing remains required.
