# R8 runtime update channel

This path is independent of stable/content-v4, stable/content-v3 and stable/latest.json. `latest.json` initially contains `{"status":"unreleased"}`: no client installs anything. A signing probe, if present, is **not an installable manifest**. Do not copy it into latest.json.

After actual R8 Windows field validation, create an Actions artifact named `r8-runtime-release-candidate` with root payload.json and blobs/<sha256>.bin only, using the R8 prepare-feed tool on reviewed baseline and target programs. No school data, credentials, profiles, private keys or installer bootstrap files. The first allowed base set is the exact three V1.66.0, V1.66.1 and V1.66.2 R8 review release.json hashes in tools/r8-publisher/validate.py. Initial target must be newer than all three. Do not activate a release until field validation and baseline promotion. For later releases include the previous signed bases plus previous release.json digest. The publisher refuses a missing ancestor, silent removal, downgrade, unknown file or changed blob.

Run [R8 verified runtime release](../../.github/workflows/r8-runtime-release.yml) manually with the candidate artifact ID, its archive SHA256, manifest SHA256, and explicit field gate. Existing teacher-tools-signing environment signs only the validated bytes. Independent publisher checks the signature again, existing channel digest and all blobs, then commits the complete snapshot in one git commit (no force push). Pages build is requested separately; confirm live manifest/blob hash before declaring deployment. The R8 installer is not part of this workflow. Existing update channels remain untouched.
